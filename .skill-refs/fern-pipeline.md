# How rivermarkets-python-sdk is built

The SDK is generated; almost nothing in `rivermarkets/` is hand-maintained.

## Pipeline (what regen.sh does)

1. `fern/openapi.raw.json` — full spec fetched from the API (in this skill:
   copied from `../openapi-spec/backend/openapi.json`).
2. `python3 fern/filter_spec.py` — reads `openapi.raw.json`, keeps only the
   `(path, method)` pairs in its `ALLOWED` set (the publicly documented
   surface, mirroring docs.rivermarkets.com/api-reference), prunes orphan
   component schemas, writes `fern/openapi.json`.
3. `fern generate --local` (needs Docker — runs in SDK CI, never on this box)
   — consumes `fern/openapi.json` per `fern/generators.yml`, wipes and
   rewrites `rivermarkets/`.
4. `python3 fern/postprocess.py` — re-applies hand-written code on top.

## Generated vs hand-written

- Generated (never edit): everything under `rivermarkets/` except what
  postprocess copies in. Regenerated by SDK CI on every PR touching `fern/`.
- Hand-written (edit only mechanically, lives in `fern/templates/`):
  `auth.py` (Ed25519 request signing), `environment.py` (base URLs),
  `fee_calculator.py`, `realtime/` (websocket client, messages, signing).
  `postprocess.py` also rewrites `rivermarkets/client.py` from a template and
  patches `__init__.py` re-exports.

## What this skill may change

- `fern/openapi.json` — always via `filter_spec.py`, never by hand-editing
  the JSON.
- `fern/filter_spec.py` — only the `ALLOWED` set, only for endpoints that are
  publicly documented in river-markets `mintlify-docs/api-reference/`.
- `fern/templates/*` — mechanical, unambiguous fixes only.

## After the PR opens

The SDK repo's `regen` workflow regenerates `rivermarkets/**` and pushes the
result onto the PR branch, then codex reviews the whole diff. If postprocess
or the generator fails there, the PR's checks go red — that is the signal a
human must look at the generator contract, not something to patch around by
editing generated files.
